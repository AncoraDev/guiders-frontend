Documentación API

Cómo se llama

{{ providerLabel() }} llama a Guiders desde su servidor. La clave de integración va en la cabecera x-api-key (gdr_live_… o gdr_test_…). El companyId del cuerpo es el UUID del cliente y tiene que coincidir con esa clave.

El comercial no entra por Keycloak. Entra cuando {{ providerLabel() }} abre Console en un iframe con el token de la segunda llamada.

POST /api/v2/integration/commercials/sync

Sincronizar un comercial

Alta, cambio o baja. Si el id externo ya existe en esta empresa, Guiders actualiza la cuenta. active: false la deja inactiva y no la borra.

Cuerpo

Campo Obligatorio Qué es
companyId Sí UUID del cliente de la clave.
externalUserId Sí Id del comercial en {{ providerLabel() }}. Máximo 128 caracteres.
email Sí Email del comercial.
firstName Sí Nombre. Máximo 80 caracteres.
lastName No Apellidos. Máximo 80 caracteres.
roles No commercial, supervisor o admin. Si no se envía, es comercial.
active No Por defecto true. false da de baja al comercial.

Login del comercial

{{ providerLabel() }} muestra Console en un iframe. Cuando el iframe está listo, pide este token y se lo devuelve. Console abre Atención ya con la sesión. El token dura 8 horas.

Iframe

{{ iframeExample() }}
  1. El iframe envía guiders:v1:ready con payload.version 1.0.0.
  2. {{ providerLabel() }} llama a esta ruta y recibe el token.
  3. {{ providerLabel() }} responde al iframe con {{ authMessage() }}, payload.token y payload.userId.
  4. Para salir, {{ providerLabel() }} envía {{ logoutMessage() }} con payload vacío.

Errores

Código Cuándo
401 La clave no va en x-api-key, no empieza por gdr_live_ o gdr_test_, o está revocada.
403 El companyId no es el de la clave, el embed está apagado, o el comercial no existe o está inactivo.
400 Falta el email, el nombre o un id de comercial. En el login hay que enviar externalUserId o userId.
409 Ese email ya pertenece a otra cuenta.
